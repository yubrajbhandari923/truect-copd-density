## Findings so far

### File-level inventory (job 204679, snapshot `code/a9cb380`, evidence `results/e00/inventory.json`)

Observed, all 67 subjects:

- Pairing map has 67 rows, 67 unique IDs, 67 unique projection series; the ID sets of
  phantoms, recons, material tables and LAC folders are identical to it. No unmapped series.
- Every phantom `.bin` size equals the product of its filename dims. Shapes differ for every
  subject (z 996–1540, y 1416–2166, x 872–1624 voxels).
- Recon DICOMs are **MATLAB secondary captures (Modality OT) with no geometry or rescale
  tags**: no PixelSpacing, SliceThickness, positions, orientation, RescaleSlope/Intercept.
  768×768 int16, `SmallestImagePixelValue` −1000. Voxel size and orientation can only be
  established by registration to the phantom.
- Slice counts are exactly 64 × rotations: 448 (2 subjects), 512 (20), 576 (32), 640 (13),
  matching 7000/8000/9000/10000 projection views. One reconstruction per subject; no
  reconstruction variants exist (affects plan A16: trigger not met).
- Material tables: identical header in all 67 (13 element columns Z = 1, 6, 7, 8, 11, 12, 15,
  16, 17, 19, 20, 26, 53; Density; Organ ID; MC ID). **The same 53 organ IDs with the same
  names and MC IDs appear in every table** → label IDs are a global ontology, not case-local.
  xlsx and `conversion_table_*.in` agree for every ID in every subject.
- Densities are **subject-specific**: every table file and every LAC file is unique. Typical
  spread is a few percent (e.g. body 0.905–0.935, muscle 1.037–1.065 g/cm³); emphysema
  (ID 60) spans 0.023–0.083 g/cm³.
- Element mass fractions sum to 0.962–1.0 (not always 1; to be explained).

Inference: a train-derived canonical catalogue can carry label → name/MC ID exactly, but a
single canonical density per label discards a per-subject offset of a few percent. Whether
that offset is recoverable from CT intensity is an empirical question for E01/E02.

Open: the 64-slices-per-rotation pattern with 35.05 mm collimation suggests a slice spacing
of 0.5476 mm; the prior single-case study (10313) fitted 0.6 mm isotropic. Being tested per
subject by the alignment fit.

### Content-level stats (job 204680, COMPLETED 6m58s; summarised by `summarize.py`, snapshot `code/3e3cc43`)

Evidence: `reports/e00/{subjects_67.json, ontology.json, cohort_facts.json}` (full per-subject
histograms stay on HPC in `results/e00/volume_stats/`).

- **No duplicate or derivative phantoms detected**: 67 distinct phantom SHA-256, distinct label
  histograms, distinct shapes, distinct density tables. (Does not rule out anatomically related
  phantoms built from one base anatomy; none is indicated by file evidence.)
- Exactly **47 of the 53 table IDs occur as voxels in every subject**. Never present: 26
  (lowest lung-parenchyma bin) and 106–110 (`lung`). No voxel label lacks a table row.
- **Elemental compositions are identical across subjects for every ID** (spread 0). Only
  density varies, and it varies as **one multiplicative factor per tissue group per subject**
  (e.g. all lung-parenchyma bins share a factor, CV 1.9%; spine cortical + trabecular share
  one, CV 0.7%; body 1.0%; muscle 0.8%). Emphysema (ID 60) is the exception: CV 35%
  (0.023–0.083 g/cm3), i.e. a genuinely subject-specific density.
- Emphysema voxels are 0%–77% of lung voxels (median 5%): disease burden varies enormously
  and should be balanced across splits.
- Recon: all 768x768, int16, minimum exactly -1000 in every subject with 39–55% of voxels at
  that value (clipped air/outside FOV). Maximum 685–7144; the few very high maxima need a
  look (artefact vs dense bone).

Consequence for targets: labels + a fixed composition catalogue are exact for all subjects;
the unknown per subject is ~10 tissue-group density factors plus the emphysema density.

### DukeSim input contract (subagent, read-only; evidence `reports/e00/dukesim_contract.md`)

- **DukeSim v1.2.21 is installed** at `/home/dmf46/DukeSim_v1.2.21` (manual + Python source);
  lab batch tool `/scratch/railabs/g-dukesimbatch` supports the Duke-1 scanner used by TrueCT.
  No run was made (writes to a shared lab folder, needs GPUs → owner decision).
- The **xlsx is the master input**: DukeSim's `full_materials.py` derives the LAC `.bin`, the
  `.in` table and `.mcgpu` files from it. A run needs: uint8 label `.bin`, grid dims, voxel
  size, NumberOfMaterials = 121, and one xlsx (Name | Z columns | Density | Organ ID | MC ID).
- LAC row = density x composition exactly; label indexes the LAC row directly. Hierarchy:
  53 organ IDs -> 19 names -> 9 MC IDs -> 8 distinct compositions.
- Density varies as **16 per-subject group scale factors**: soft tissue/bone within +-2%,
  lung 4–6%, emphysema 0.43–1.59x median. A train-derived catalogue therefore loses nothing
  on labels/compositions, <=2% density on soft tissue and bone, ~5% on lung, up to ~58% on
  emphysema unless emphysema density is predicted per subject.
- Z_eff is a pure function of the label (8 fixed compositions) → adds no information; the
  plan's optional Valand-style Z_eff analysis is not worth running as a separate target.
- Mass fractions sum to 0.962–0.968 for lung/skin (DukeSim renormalises); argon in air is
  entered in the Z=17 column. Filename terms smeared/textured/eroded/flipped are undocumented.
- Proposed export schema and validator invariants V1–V14 are in the contract file; the
  validator self-test (regenerate source `.in`/LAC from source xlsx) is not yet implemented.
